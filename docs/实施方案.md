# 通用电机 PI 整定平台：V1 半自动优化 + V2 全自动整定

> 面向编程助手的实施规格，2026-11-03。**先完成 V1，再扩展 V2；两个版本可以分别安装、分别调用。**

## 0. 首要边界（必须遵守）

1. **现有固件已经负责默认 PI 加载和正常电机控制**。本项目只实现整定；整定工具启动时仅读取当前 PI 作基线，不重复默认初始化、不重写现有驱动/通信、不自动使能或移动电机。
2. 整定核心分成 **软件整定算法层** 和 **数据适配层**。前者绝不直接导入 TMC6460 寄存器定义；后者把 TMC6460 RTMI/命令翻译为芯片无关的信号和 PI 参数。将来增加其他芯片时只增加适配器。
3. 上位机增加一个“PI 整定”标签页。**V1 半自动、V2 自动**有独立入口/API，V1 不依赖 V2 可选依赖。可复用公共曲线、指标与配置控件。
4. V1/V2 **均支持**电流 Id/Iq 的 `共用一套 PI（联动粗调）`（默认）和 `独立 PI（细调）`（可选）。共用时两个寄存器仍独立写入，两个轴仍独立验证。
5. **计算基础必须采用 `python-control` + SciPy**。`ktune` 为测试/指标/图表的架构参考，`foc-sysid` 为 V2 辨识参考，ODrive/SimpleFOC 为级联控制、试验激励参考。不得将任何参考仓库误称为可直接兼容 TMC6460 的成品整定器。
6. 测试最小化：利用 mock、合成日志和一次低风险实测，保留简单 README 和简短验收记录；不要过度设计文档/长时间压力测试。

## 1. 两个版本的功能边界

| 能力 | V1 半自动（先实现） | V2 完整自动（后实现） |
|---|---|---|
| 独立入口、设备选择、读当前 PI | 必须 | 复用 |
| 电流 d/q 共用 PI 粗调 / 独立 PI 细调 | 必须 | 必须 |
| 电流、速度、位置分层整定 | 必须；支持仅选一层 | 自动选择层级并检查依赖 |
| 位置阶跃 + RTMI 采集、指标分析 | 必须，首先交付 | 复用 |
| 速度与 d/q 电流阶跃 | 有安全激励、足够采样能力才启用；否则显示不可用/支持离线分析 | 全自动前必须验证能力 |
| 候选 PI 算法 | 从当前 PI 附近生成有界候选，标明不确定性 | 模型辨识+受约束优化 |
| 应用候选 | 用户确认、写入读回、重复测试、接受/回滚 | 启动前授权安全范围，自动多轮验证与回滚 |
| 正弦、Chirp、Bode、相干度 | 非 V1 必需，仅留接口 | 核心能力 |
| 系统辨识及自动试验设计 | 不强制 | 必须 |
| 离线日志回放 / 简短报告 | 必须 | 必须 |

**不是加载默认 PI 的模块**：所有测试从现有固件已经设定的 PI 出发。典型链路：`读取当前值 → 选层 → 测量 → 自动提出候选 → 人工批准试用 → 验证/回滚`。V2 才在用户授权的保护范围内自行连续迭代。

## 3. 软件架构：严格两层，UI 独立展示

```text
现有上位机 → PI 整定标签页 → TuningService（v1/v2 两个入口）
                                        │
                   ┌────────────────────┴──────────────────┐
                   ▼                                       ▼
       【软件整定算法层】                         【数据适配层】
        tuning_core/                                adapters/
        ├─ contracts.py                            ├─ base.py (MotorTuningAdapter)
        ├─ metrics.py                              ├─ mock_adapter.py
        ├─ experiment_specs.py                     └─ tmc6460/
        ├─ objective.py                               ├─ register_codec.py
        ├─ modeling.py (python-control)                ├─ rtmi_decoder.py
        ├─ v1/                                         ├─ scheduler.py
        │  ├─ step_analyzer.py                         └─ adapter.py
        │  ├─ candidate_search.py                   未来: other_chip_adapter/
        │  └─ workflow.py
        └─ v2/（可选部署）
           ├─ identification.py
           ├─ frequency_response.py
           ├─ auto_optimizer.py
           └─ workflow.py
                                        │
                                 已有 HPM 控制接口
                                   TMC6460 RTMI
```

- **算法层不 import TMC6460 / UART / RS485 / 寄存器地址**，只接受抽象目标值、反馈流、PI 向量、参数限制、样本时间和质量信息。UI 也不直接读写芯片寄存器。
- **数据适配层**负责 RTMI 帧解析、CRC/缺帧、寄存器映射、原始 PI 定点量化、RPM/角度/电流单位换算、主控通信时隙、安全停机、参数试用/恢复；不决定哪组 PI 最优。
- `MotorTuningAdapter` 最小契约：`capabilities()`、`read_pi()`、`snapshot_configuration()`、`start_test(spec)`、`stream_samples()`、`stop_test()`、`apply_candidate(pi,approved)`、`restore(snapshot)`、`read_faults()`。
- 数据契约至少包含：`device_id, motor_id, loop, test_id, timestamp, target, actual, velocity, id_current, iq_current, flags, units, sample_rate, dropped_frames, config_snapshot`。时间戳需明确产生位置；不同通道未同步时不得假设属于同一个采样时刻。
- 独立调用建议：`V1SemiAutoTuner(adapter).analyze_and_propose(spec)` / `verify_approved_candidate(...)`；`V2AutoTuner(adapter).autotune(spec, safety_authorization)`。V2 包不存在时 V1 正常运行。
- 保持默认 PI 流程原样：整定工具读取当前 PI 作为 baseline；只有试用候选时根据用户批准走已有配置写入接口；持久化沿用已有固件/上位机机制，不能整定工具静默修改启动默认值。

## 4. 分层整定与 d/q 选项

**初始条件**：设备已由固件正常加载所有 PI，可在安全条件下运行。分层指整定优先级，不指默认初始化次序。通常优先验证 `Id/Iq 电流环 → 速度环 → 位置环`。用户也可选择仅位置环整定，但应核查内层环的现有稳定性与验证记录；变更内环后，外环原有验证状态需要重新确认。

- `DQ_SHARED`（默认，**V1/V2 均支持**）：优化变量仅 `kp,ki` 两个，设备端分别写入 `0x142` 和 `0x143`。**Id/Iq 的数据质量和跟踪表现分别评价**；任一轴不达标不能声称粗调完成。
- `DQ_INDEPENDENT`（可选细调，**V1/V2 均支持**）：优化变量 `kp_d,ki_d,kp_q,ki_q`；可只选择某一轴测试，另一个轴保留其当前值。切换时可将共用 PI 复制为独立 PI 的起点。
- 电流环 PI 在 TMC 中为 `0x142 FOC.PID_FLUX_COEFF` 和 `0x143 FOC.PID_TORQUE_COEFF`；速度 `0x145`，位置 `0x146`；共享归一化 `0x140`。芯片各 P/I 为有符号 16-bit 字段，需考虑 Q 格式、采样频率、`VELOCITY_SHIFT` 等。**不能将算法层浮点 Kp/Ki 当作 TMC 寄存器原始数字直接写入。**
- 对电流环需要**适当的 d/q 电流目标激励与足够快的 Id/Iq 实测采样**。仅能设置 d/q PI 且只能低速 RTMI 读数时，V1 允许给出基于 R/L 模型的受约束初值/人工试用，不允许伪称完成高速电流环阶跃优化；V2 遇带宽不够必须拒绝该环的自动整定。

## 5. V1 实现细则：半自动优化的完整闭环

状态：`IDLE → READ_BASELINE → READY → TESTING → ANALYZING → PROPOSED → AWAIT_USER_APPROVAL → APPLYING → VERIFYING → ACCEPTED / ROLLED_BACK / FAILED`。

1. **选择环和试验**：位置环优先做小行程绝对位置阶跃，`MOTION_MODE=POSITION, RAMP_EN=0`；速度和电流阶跃只在硬件/安全能力允许时开放。选择电机、d/q 模式、测试幅值、保持时间、最大安全速度/行程/电流、超时。动作前要求明确用户授权。
2. **基线快照**：读当前 PI、归一化、控制模式、限幅、目标、反馈配置；只读取，不修改默认值。原值用于试用失败后的恢复。
3. **受控试验+RTMI**：记录目标变更前稳定段、**目标生效时间**、目标/实际/速度和可用的 PI 输入/积分/电流，以及采样质量。针对 TMC 半双工 RS485，RTMI 主动流可能和目标写入冲突，必须先复用/验证 HPM 的时隙调度；没有无冲突办法时先允许离线导入日志，不允许边写目标边假装 RTMI 帧可靠。
4. **计算指标**：最大绝对超调、按运动方向定义的超调率、10-90% 上升时间、指定误差带稳定时间、末端稳态误差、RMS 跟踪误差、振荡/反向次数、峰值实际速度，以及电流环采样充足时的 Id/Iq 误差与饱和。若阶跃幅度为零、时间戳倒退、目标没生效、严重缺帧或严重限幅饱和，结果标记 `REJECTED`，不推荐 PI。
5. **自动候选**：使用 `python-control` 对简单可辨识代理模型做时间响应检查，SciPy `least_squares`/`minimize` 在**当前已验证 PI 附近、带边界**搜索候选；记录模型误差/不确定性。超调率不能直接换算 PI。无可靠模型时也可给“限制范围内试调候选”但要标明经验型，不声称精准预测。候选经寄存器量化/范围检查，避免实际写值落在不允许范围。
6. **人工确认试用**：显示原 PI/候选 PI 与估计依据，用户点击批准后在可控/安全状态写入并读回；执行同条件小行程验证，实测比较指标。通过后可确认保存；失败/中断则停止、记录、按主控保护条件恢复原 PI，不可在未知运动状态强行回写。
7. **单层模式**：已经验证的内环可以跳过；若改变电流环，则速度和位置环的有效验证标识需重新检查。

**V1 结果必须是“可试用的候选 PI + 明确的证据、用户审批、验证和回滚”，不是只有曲线和一段建议。** 对未验证的环显示“待适配/采样带宽不足”，不能以模拟测试冒充真机完成。

## 6. V2 实现细则：完整自动整定

- 在已完成 V1 后单独启用 `v2` 可选包与入口；V1 无需 V2 依赖。
- V2 沿用 `shared/independent` 选择。允许根据已有验证记录跳过某内环，默认仍按电流 → 速度 → 位置的层级检查，不能自动忽略内环不稳定。
- 增加**自动激励设计**（受机械边界、Iq、速度、位移、测试次数、单次时长限制）；在采样满足条件时增加 sine/chirp，按 `foc-sysid` 思路计算 CSD/Welch/coherence 和带宽等；采样不足时只保留可靠的时域辨识。
- 用 `python-control` 建立/评估响应模型、在**已构建的开环模型**上做裕度计算；SciPy `least_squares` 拟合模型、`minimize`/`differential_evolution` 先在**模型**上寻找候选，再只让少量通过筛选的候选参与真实测试。
- 用户启动前一次性确认安全包络；系统可以在范围内自动多轮试验、评价、回滚/接受，但 HPM 主控必须有独立于上位机通信的保护/停止路径。V2 不自动绕开原固件的供电管理、使能和故障策略。
- 结束生成每环测试与模型质量、候选记录、最终 P/I（含 TMC 原始量化值）、验证结果；任何测试能力不足或置信度低时停止/降级，不允许假完成。

## 7. TMC6460 RTMI 适配重点

- RTMI `UART.CONTROL 0x340`、`UART.RTMI_CH_0..7 0x344..0x34B`；最小位置测试目标 `0x152`、实际位置 `0x155`、实际速度 `0x154`；可增加位置误差、位置 PI 输出的速度目标和积分状态。电流 Id/Iq 实际/目标的**精确寄存器地址和编码必须由 TMC6460 Rev.0 手册及现有代码核实**，不可杜撰。
- 解码 RTMI 输出帧、可选 CRC、时序、各通道值、误包/丢包；关键测量必须知道采样频率与真实目标更新时间。RTMI 的连续发送与半双工命令写入需要已有 HPM 调度接口协调。
- 把能力声明放进 `capabilities`：`position_step / velocity_step / id_step / iq_step / chirp / telemetry_hz / safe_stop / rollback / timestamp_quality`。能力不足时禁用相应测试。
- 单位层区分真实物理增益与寄存器编码，RPM 转换取决于反馈配置；位置是单圈值还是累计位置必须清楚。注意写 `0x155` 可能影响位置目标，整定时只读该寄存器。
- 日志格式建议 `CSV + 元信息 JSON`，含原值、候选、使能状态、采样率、时间戳、是否通过和设备配置快照。算法层输入使用统一物理单位和明确定义的时间轴。

## 8. 最小实施顺序与简单验收

**V1 四步，不要扩张为大型项目：**

1. 读现有上位机/固件通信架构，建立两层协议及 mock adapter，合成位置阶跃日志验证指标；完成 V1/V2 独立入口框架。
2. 接现有 TMC RTMI、当前 PI 读取、单次安全位置阶跃日志；优先解决 RS485 冲突，不能安全实时收发时先支持离线日志导入。
3. SciPy + python-control 候选/可行性分析，人工批准试用、对比验证、停止与回滚；先实现位置环。
4. 扩展速度环及 d/q 共用/独立 UI 与参数通路，按设备能力选择是否能做实测电流阶跃。V1 完成后冻结接口再开发 V2。

**V2 两步：** 一次离线频域/模型辨识 + 优化；一次一台电机、短时、受限的全自动实测验证。

**足够的验收用例**：2 份合成阶跃（零超调、有超调）、1 份缺帧日志、1 次 mock 试用+回滚、1 次真实低风险位置阶跃；V2 再加 1 份合成 chirp/频响和 1 次受约束自动试验。测试结果只需简短记录，不写冗长过程报告。电流环未经采样/激励实测时必须标注“功能已接入、自动优化待验证”。
